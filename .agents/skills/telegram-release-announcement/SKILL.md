# 以 Telegram 富文本整理更新公告

从当前项目的 Git 记录和实际代码整理可发布的更新公告，转换为 Telegram macOS 原生富文本并写入剪贴板。用户无需提供公告草稿。

## 确定版本范围

- 用户指定版本、分支或比较范围时按其要求处理
- 未指定版本时，先查看当前分支、远程跟踪关系和版本标签，默认整理最近正式版本相对上一正式版本的变化
- 使用 Git 历史确认标签的先后与包含关系，不按标签名称的字典序判断版本，也不将当前工作分支直接当成发布版本
- 本地记录足够时直接继续，仅在目标版本存在歧义且影响公告内容时询问
- 用户要求 pull 或 fetch 时执行对应操作，其他情况先使用本地已有记录，远程访问遵循当前任务授权

## 从 Git 核对内容

读取比较范围内的提交、完整提交说明和文件差异，再沿相关调用链核对实际行为。提交标题用于定位改动，不能直接充当全部公告依据。

- 区分新增功能、缺陷修复、重构、依赖与构建变更，合并同一功能的重复描述
- 一个提交或 PR 内的多项改动按用户可感知的功能归纳，不遗漏会影响升级的重要变更
- 核对配置项、默认值、生效条件、限制、重试次数和错误处理，按代码实际行为描述
- 单独检查发布产物、镜像、配置和接口的移除或变更，据此说明升级影响
- 数量与正文使用同一统计口径，依赖升级单独计数，避免把 PR 数量写成缺陷数量
- 版本号与比较基线从 Git 获取，下载链接按项目远程仓库及目标版本构造
- 发布日期优先使用已确认的发布记录，不把提交或标签日期直接写成发布日期
- 需要发布记录或 PR 补充信息时，使用 GitHub 连接器读取明确的目标，不擅自搜索

贡献者从该版本范围内的作者和 Co-authored-by 记录整理，结合仓库已有身份映射合并别名。仅按该范围列出署名，不因当前用户参与整理公告就将其加入。AI 助手的不同模型名称合并到助手名称，例如 Claude Opus 与 Claude 统一列为 Claude，保留记录中实际出现的其他贡献者。

## 整理公告

默认先中文后英文，两种语言的事实、数量与升级提示保持一致。使用自然、直接的发布文案，说明具体改动及其影响，不加入调查过程、泛泛宣传或未经验证的使用场景。

以下为排版示例，分节按本版本实际改动增删或合并。没有对应内容的分节直接省略，示例未覆盖的内容可新增合适的分节，不固定分类或分节数量：

1. 项目名称、版本号和 🚀
2. 下载地址 / Download
3. 简短版本介绍及版本概览，交代比较基线
4. 🚀 新增功能
5. 🐞 云盘驱动修复
6. 🌱 传输与流式读取
7. 🛡 安全与稳定性
8. 🧩 其他修复
9. 📦 依赖与构建
10. ⚠️ 升级提示
11. ❤️ 感谢所有贡献者以及社区用户的反馈与支持
12. 英文公告，沿用对应分节

分节内使用编号及与内容对应的 emoji，适当强调功能名称，相关条目保留已有 PR 编号。用户指定格式或语言时以其要求为准。

不要将增量保存写成断点恢复，不将有限重试写成保证成功，也不根据一个响应字段变更推测客户端后续行为。清空数据、重新生成文件等升级操作必须有实际变更依据。没有对应依据时省略，不用免责措辞补足。

交付前逐项对照版本差异，检查正文数量、贡献者去重、中英文一致性，以及升级提示是否覆盖实际移除或变更的内容。只陈述源码和已执行检查支持的结论。

## 富文本交付

读取 [原生剪贴板格式](references/native-clipboard.md)，将公告构造成 Document。标题、强调、编号列表和链接使用结构化字段，保留分节和段落顺序，不把 Markdown 标记写入显示文本。

保留一份可读文本和 HTML 预览，文件中只包含交付公告。使用现有运行时调用 AppKit 的 NSPasteboard，例如 osascript 的 JavaScript for Automation，写入原生 Document、纯文本和 HTML，无需安装依赖。执行权限遵循当前环境规则。

需要直接进入 Telegram 新富文本编辑器时，必须写入专用类型。普通文本或 HTML 复制不能替代该载荷。

写入成功后不再执行会覆盖剪贴板的命令。最终回复简短告知已就绪，可按 Command+V 粘贴，并附预览链接。分别陈述剪贴板写入结果与 Telegram 实际粘贴效果，只报告执行过的验证。
